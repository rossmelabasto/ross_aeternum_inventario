01 · El proyecto

Una tienda real, con un problema real

El problema

Aeternum vende tenis y ropa de segunda mano por redes. La demanda existe; lo que frena es el trabajo manual: saber qué queda en stock y registrar cada venta.

El objetivo

Un sistema web de inventario y ventas: base de datos en la nube, API documentada y una tienda 3D conectada a datos en vivo.

  • 3 tablas en Supabase
  • API REST con Swagger
  • Tienda 3D recorrible

id · producto_id

canal

  • Seguridad por filas (RLS): el público solo lee el catálogo; las ventas solo las ve el backend.
  • La API entra con un rol propio que no puede borrar ventas, no con el usuario postgres.
  • Migraciones numeradas (001–005): al sumar ropa, la talla pasó a texto y se agregaron color y tipo.
04 · API REST

FastAPI + Swagger

with p as (
  update productos set stock = stock - :c
  where id = :id and stock >= :c
  returning ...)
insert into ventas ... from p
Vender sin quedar en negativo

Una sola sentencia: descuenta y registra a la vez. 10 compras simultáneas del mismo par con 3 en stock → 3 ventas, 7 rechazos (409).

Validación automática

Pydantic responde 422 si llega un precio negativo o una talla vacía.

05 · Gráficos 3D

Una tienda que se recorre

  • Primera persona: W A S D y mouse, como un videojuego.
  • Las secciones salen solas de la base: calzado en repisas, ropa en rieles, gorras en la mesa.
  • Clic en un producto → ficha y "Vender 1 unidad".
  • Buscador que te lleva caminando y minimapa.
  • Modelos hechos con código en Three.js.
